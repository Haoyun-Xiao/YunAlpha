# 基金经理投资手册生成 Skill（fund-manager-handbook）

> 本 skill 兼容 Anthropic Claude Code、OpenAI Codex CLI、OpenCode 原生 Agent Skills 规范，亦适用于 Cursor / Windsurf / Cline 等支持 SKILL.md 加载的环境。

## 1. 何时使用本 skill

**触发条件**（任一满足即可）：

- 用户提供 1 份及以上基金经理文档（文件名常含「定期报告」「运作分析」「季报」「年报」「路演」「访谈」「交流」），并请求"生成投资手册""做成研究报告""按 Part 输出""10 个 Part""结构化输出""知行合一""配置建议"等。
- 用户给出 `Part1…Part10` 标题列表或等价的 10 部分结构，要求依文档撰写。
- 用户引用与基金经理"投资理念 + 投资案例复盘 + 配置建议"高度相关的输出意图。

**不要触发的场景**：单纯研报摘要、选股建议、行情预测、与基金经理无关的提问。

## 2. 不可违反的硬约束（按优先级降序）

1. **禁止联网搜索、禁止引用文档以外的任何信息**（包括训练数据中的外部知识、研报、新闻、宏观数据、第三方观点、指数点位、个股代码）——**Part1教育背景字段除外**。教育背景（学校、专业、年份）在文档未提及时，允许通过外部知识（MCP服务器、训练数据中的公开信息）补充。其余一切内容仍禁止外部引用。这是最高优先级约束。
2. **基于已有信息输出**，不添加材料未提及的背景或主观解读——Part1教育背景字段除外。教育背景允许通过外部知识补充，但必须明确标注来源。
3. **核心信息必须来自原文**（Part1教育背景除外），保留原文关键术语（如"赔率优先""价值为盾，成长为矛""自下而上""低估值+好公司""概率驱动""逆向投资""周期+概率""春夏秋冬"等），减少改写，**侧重整合而非总结**。
4. **文档优先级**：「定期报告运作分析」= 主文档；「路演/访谈/公开交流」= 补充文档。两者冲突以"定期报告"为准。
5. **禁止使用"路演材料中提到""他在路演中说""他在访谈中表示"等冗余归因前缀**。信息直接呈现，而非陈述"谁在说"。例：不要写"路演材料中提到，刘旭为厦门大学管理学硕士"，直接写"刘旭为厦门大学管理学硕士"。仅当需要区分不同时间点观点冲突时才使用简短的归因（如"2023年路演中补充："），且应保持极简。
6. **不要在各 Part 开头添加"承接上文"式的过渡阐述段**。直接以 Part 标题和子标题开始内容陈述。例如不要写"理解了Part1的内容后，接下来需要深入..."，直接进入子标题正文。每个 Part 末尾也不需"引出下文"的预告句。
7. **保持段落简洁直接**：每段直接陈述事实和判断，不加冗余的引导前缀。禁止出现"以下通过XXX展开""接下来需要深入""我们来看看"等叙述性过渡句。
8. **字段读取异常须显式标注**：若任何字段因过长被截断或解析失败，在报告最前方加一行 `⚠️ 字段读取异常：<文件名>::<字段路径>（原因：<截断/编码/缺失>）`。
9. **大标题严格沿用 Part 原始措辞**，不重写、不简化、不翻译，含括号内提示语。详见 `references/parts.md`。
10. **段落须有"起承转合"**：每个段落按"事实陈述→原文印证"二层结构组织。先直接陈述事实或判断，再以原文佐证。避免纯原文拼接，也避免过度评述。评述句（1-2句）应简洁提炼洞察，不得过度展开。禁止整段仅有引用而无事实陈述。
11. **采用"事实+分析"双层结构**：在每个 Part 的小节或案例末尾，可增加简洁的"小结与思考"（1-2句），提炼该节的关键模式。Part4所有案例末尾统一加简洁的"案例启示"段（2-3句），Part3每年末尾加简洁的"年度模式总结"段。不得只罗列原文而不做任何提炼。
12. **建立跨 Part 逻辑闭环**：Part4 的每个成功/失败案例中须标注对应的核心理念（如"体现其安全边际优先原则""契合自下而上选股框架"），Part7 表格的"市场观点"列引用 Part3 对应年份的判断原文。各 Part 应通过交叉引用形成逻辑闭环，而非各自孤立。

13. **禁止输出 `<!-- 待续：PartX-Y -->` 等分批占位标记**：任何形式的 HTML 注释标记或占位符均不得出现在报告正文中。分批模式下，每批必须产出完整的 Part 内容（不含"待续"标记）。如需分批，直接按顺序写完当前批次的全部 Part 后结束，下一批通过 Edit 追加。

完整 6 条逐字版 + 衍生执行细则见 `references/rules.md`。

## 3. 输入识别与文档判定

**主文档判定**（满足任一即视为主文档）：
- 文件名含「定期报告」「运作分析」「季报」「年报」「定期」之一。
- 文件内容为 JSON 且键名含 `基金投资策略和运作分析` 或 `宏观经济证券市场及行业走势展望`。

**补充文档判定**：文件名含「路演」「访谈」「交流」「公开」「问答」「会议纪要」之一。

**私募文档判定**：文件名含「私募」关键词的，自动标记为私募时期材料。私募文档在文档类型判定上遵循上述主文档/补充文档规则，额外附加时期标签。

未明示时按上述规则自动判定。

**文档时期分组**：当输入目录中同时存在含"私募"关键词的文件和普通文件时，视为"公募+私募混合"模式。各 Part 引用私募文档内容时，在引用处末尾标注（私募时期）。仅含普通文件时视为纯公募模式，行为不变。

## 4. 输出契约

- **文件名**：`<基金经理名>_report.md`，写入用户当前工作目录（或用户指定路径）。若文件已存在则自动追加 `_v2 / _v3` 后缀避免覆盖。
- **全文字数**：**≥ 30,000 字**。各 Part 字数分配见 `references/parts.md` 中的"字数分配表"。
- **分批模式**（默认建议 3 批：Part1-5 / Part6-8 / Part9-10）。后续批次用 Edit 在同一文件 append，不要新建。**禁止输出 `<!-- 待续：PartX-Y -->` 等 HTML 注释标记**。
- **报告开头摘要**：报告标题下方以 `> **基金经理投资摘要**：` 开头，用一段话（250-400字）概括基金经理，覆盖核心投资哲学、从业年限与框架迭代、代表业绩、与市场主流的核心差异、适合的投资者类型。示例格式见 `references/output-format.md`。禁止在摘要中说明数据来源——数据来源信息不属于报告摘要。
- **Part 标题**：必须以 `## PartX：<原始标题>` 起始（原始标题完整保留，含括号内文字）。
- **Part 内部结构**：每个 Part 必须按照 `references/parts.md` 中定义的子标题结构组织，详见 `references/rules.md` § 2.8。
- **Part7 强制为 Markdown 表格**，列名固定 `阶段/事件 | 市场观点 | 投资操作 | 与核心投资理念契合/不契合 | 客观评价`；"与核心投资理念契合/不契合"取值仅 `契合 / 部分契合 / 不契合`；推荐 **10-18 行**，下限 10 行。
- **Part10 数值（持有周期、配置比例、建仓节奏）必须可由文档推得**，且每个数字范围后须有简要理由。文档无依据时仅写定性描述，不下具体数字，不凭空生成。禁止在报告中出现"依据：PartX"等引用式标注——理由应当融入正文自然叙述。
- **Part 开头直接进入内容**：每个 Part 直接以子标题内容开头，无需"承接上文"过渡句。**禁止**在 Part 开头添加类似"理解了PartX的内容后，接下来需要深入..."的过渡阐述。**禁止**在 Part 末尾添加"引出下文"的预告句。Part 应直接开始和结束，不添加叙述性框架。
- **底部声明**：最后一行 `> 以上配置建议仅供参考，不构成投资建议。`

## 5. 工作流（含 1M context 与有限 context 两种模式）

### 5.1 一次性读取模式（推荐，模型 context ≥ 200K tokens 时）

1. 用 Read 工具一次性读完主文档与补充文档全文。
2. 加载并遵循以下参考文件（progressive disclosure，按需读取，不必一次性全读）：
   - `references/rules.md` — 6 条硬约束逐字版 + 衍生执行细则（含字数硬约束、子标题结构、反偏差自检）
   - `references/parts.md` — 10 Part 原始定义、取材清单、定量目标、**字数分配表**
   - `references/output-format.md` — 输出模板、表格规范、原文引用格式、各 Part 结构模板
3. 对每个 Part 先在脑中做"原文卡片清单"（句子、术语、年份、案例），再按"事实陈述→原文印证"二层结构做组织。避免使用"他认为""他指出"等引导句。同时标注跨 Part 交叉引用点（如 Part4 案例对应 Part2 的哪条理念、Part7 表对应 Part3 的哪个年份判断）。
4. **处理教育背景（新增步骤）**：在读取文档后，若文档未提供基金经理的教育背景信息，则通过 MCP 服务器（如 websearch）或训练数据中的公开知识补充学校、专业、年份，直接写入 Part1 教育背景段落，不得在报告末尾另加脚注或附录节。若外部来源也无法确认，则省略该段。
5. 按 Part 顺序写文件。分批时按用户指定批次写。
6. 每批末尾跑一遍 `## 6. 反偏差自检`，发现违规当场修正。

### 5.2 切片读取模式（context < 100K 或 docx 解析失败时）

1. 先用 Glob/Grep 定位文档中的"年份锚点"（如 `^\d{4}年[一二三四半季年].*报`），按年份切片读入。
2. 同步定位"教育背景/职业经历/能力圈/案例"等关键词附近段落，做 Part1/Part2/Part4 取材。
3. 其它步骤同 5.1。

## 6. 反偏差自检（每批生成完必跑）

- [ ] 全文总字数 ≥ 30,000 字。
- [ ] 每个 Part 字数达到 `references/parts.md` 中规定的下限。
- [ ] 每个 Part 的子标题结构与 `references/parts.md` 定义一致。
- [ ] Part1 教育背景：文档有则优先用文档；文档无教育背景时，通过 MCP/外部知识补充学校、专业、年份等信息。
- [ ] Part4 案例：成功≥3 个、失败≥2 个，每个案例 3 个子段落齐全。
- [ ] Part6 策略差异性：使用了对比表格，≥ 5 行。
- [ ] Part7 表格：行数≥ 10，"与核心投资理念契合/不契合"仅用三选一，5 列齐全。
- [ ] Part8：4 个子标题齐全，每个子标题下≥ 3 个子角度。
- [ ] Part9：评估表≥ 9 行，差异化能力圈≥ 5 条。
- [ ] Part10：每个数字/动作后带括号引证，重点跟踪维度≥ 8 条。
- [ ] 是否出现文档中**没有的**人名/机构/数字/事件/指数点位/个股代码？有则删除。
- [ ] 是否出现"我认为""我推测""一般来说""市场普遍认为"等主观或外部语气？直接陈述事实，删除冗余归因。
- [ ] 是否出现"路演材料中提到""他在路演中说""他在访谈中表示"等冗余归因前缀？直接陈述内容本身。
- [ ] Part 标题是否与 `references/parts.md` **逐字一致**（含括号内提示语，不简化、不去标点）？
- [ ] 关键术语是否原文保真（不要替换近义词，例如不要把"赔率"改为"潜在收益"）？
- [ ] 报告开头是否有 `> **基金经理投资摘要**：` 开头的摘要段落？内容是否覆盖核心投资哲学、从业年限、业绩、市场差异、适合投资者类型？
- [ ] 如果存在字段读取异常，是否在报告开头标注了？
- [ ] 底部声明是否完整？
- [ ] 每个段落是否是"事实陈述→原文印证"二层结构？是否有通段纯引用而无事实陈述？
- [ ] 每个 Part 是否有"承接上文"的过渡句或"引出下文"的预告句？有则删除，Part 应直接开始和结束。
- [ ] 是否有 `<!-- 待续：PartX-Y -->` 等 HTML 注释标记或分批占位符出现在报告正文中？有则删除。
- [ ] Part4 案例中是否标注了"见 Part2.X"的交叉引用？
- [ ] Part7 表"市场观点"列是否引用原文且每行≥50字？"投资操作"列是否≥80字？

## 7. 与外部工具的关系

本 skill 宿主 CLI 内置 Read/Write/Edit/Glob/Grep 即足够处理大部分内容。MCP 服务器的使用场景如下：

- **教育背景补充（新增）**：当文档未提供基金经理教育背景时，可通过 MCP 服务器（如 websearch / 搜索工具）获取学校、专业、年份等公开信息。补充内容直接写入 Part1 教育背景段落，不得在报告末尾另加附录节。
- **批处理多位基金经理**：可选挂 `filesystem` MCP（参考 `opencode/config-snippet.json`），用于自动遍历 `input/` 目录、产出到 `output/`。

平台部署参考：

- **Claude Code**：把本目录软链/拷贝至 `~/.claude/skills/fund-manager-handbook/`。
- **OpenAI Codex CLI**：放至 `$CODEX_HOME/skills/fund-manager-handbook/`；可选 `agents/openai.yaml` 提供 Codex UI 元数据。
- **OpenCode**：放至 `~/.config/opencode/skills/fund-manager-handbook/` 或项目内 `.opencode/skills/fund-manager-handbook/`。当前 OpenCode 可原生发现并按需加载项目 Skill，无需额外插件。

## 8. 失败模式与处理

- **文档为空或无法解析**：直接告知用户，不要编造内容；建议用户先 `head` 或 `cat` 检查文件。
- **教育背景MCP补充失败**：若 MCP 服务器不可用或搜索未返回结果，则直接省略教育背景段，不得编造。
- **文档缺少某些 Part 所需材料**（例如某经理未明显披露失败案例）：仅写文档支持的部分，不凑字数，不刻意标注缺失信息。
- **路演含多场访谈，时间跨度大**：按访谈日期归入对应年份的 Part3 小节；不要把后期访谈的判断塞进早期年份。
- **用户拒绝分批，要求一次性出全 10 Part**：照做，但提醒"单次输出可能较长，弱模型可能截断"。
- **同名文件已存在**：自动加 `_v2 / _v3` 后缀；不要覆盖。
- **字数不足 30,000 字**：必须重新扩充（优先扩充 Part3 和 Part8），不得输出不达标版本。

## 10. 输出对比分析与迭代方向

> 以下内容为使用周海栋材料进行实际输出后，将本 Skill 输出（~38,800字）与人工作业/参考文档（~23,962字）对比的总结。旨在指导后续迭代方向。

### 10.1 语言自然表达对比

| 维度 | 本 Skill 输出 | 参考文档 | 迭代方向 |
|------|-------------|---------|---------|
| 段落流畅度 | 偏"原文拼接"风格，大量直引号引用导致段落切分较碎，句子间的逻辑连接词不够丰富 | 语言自然流畅，段落有起承转合，主题句+展开+过渡的段落结构完整 | 引入段落构建模板：每段以引导句开头，中间展开原文引用，末尾加1-2句承上启下的评述 |
| 连接与过渡 | 各 Part 之间、各小节之间缺少过渡句，整体呈现"数据库式"排列 | 有清晰的逻辑递进感，Part 之间通过"总的来看""具体而言""进一步看"等连接词自然衔接 | 在 Part 开头和结尾增加过渡段落，用综述句或展望句连接前后内容 |
| 句式多样性 | 大量"他认为""他指出""他表示"等相同句式开头，读感单调 | 句式灵活多变，穿插使用"从...来看""值得注意的是""具体到..."等多种句式 | 在原文引用中引导句加入句式模板库，避免重复使用同一动词引导引用 |
| 可读性 | 信息密度高但对读者不够友好，缺少"读者视角"的引导 | 更注重读者理解，会用类比、具象化表达来帮助理解抽象概念 | 在关键概念处增加通俗化解释或类比（不超过1句），帮助非专业读者理解 |

### 10.2 内容深度与丰富度对比

### 10.4 高优先级改进项（按影响排序）

1. **采用"事实陈述→原文印证"二层段落结构**：每个子段落先直接陈述事实，再以原文佐证，避免纯引用拼接和过度评述，做到简洁有力。
2. **删除"路演中提到""他曾在访谈中说"等冗余归因前缀**：信息直接呈现，仅在需要区分时点观点冲突时使用极简归因。
3. **删除 Part 首尾过渡段**：Part 直接以子标题内容开始和结束，不添加"承接上文""引出下文"的叙述性框架。
4. **增加 Part 间交叉引用**：在 Part4 案例中标注对应的核心理念（如"体现安全边际优先原则"），在 Part7 表中引用 Part3 的对应年份，构建逻辑闭环。
5. **控制大段纯原文引用**：超过50字的原文引用应拆分为2-3句，中间穿插简洁评述，避免"引用堆砌"。
