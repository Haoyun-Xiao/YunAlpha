# 可转债规则与复核规范

适用范围：原站历史归档中的四种规则；[当前卡片](catalog.md)仅用于定位。以下证据编号见[索引](README.md#证据索引)。输入、得分、交易执行分开冻结。任何超出已见证据的选择应在研究配置里注明，不靠调整参数把旧结果补齐。

## 信号规范

一行候选对应一个市场交易日和一个转债代码。可复算的输入应包含交易日期、未复权收盘价（元）、成交量、到期日或当时剩余期限、候选资格及每条规则的所需字段。用历史有效的转债池，不以当前未摘牌名单回填；先过滤，才算截面百分位和选取数量。月度用全市场当月最后一个交易日，不从每只券的最后有效价推导。每日指每个市场交易日。遇到输入缺失记录原因；缺整日截面或尚无 T+1 行情时不要把缺失当清仓信号。

|---|---|---|---|

可执行逻辑的伪代码（实现可按 [独立截面检查](#独立截面检查) 模式使用归档字段，并显式记录降级）：

```text
for T in market_decision_dates(rule.frequency):
    rows = freeze_one_row_per_bond(T, dataset_version, calendar_version)
    eligible = rows meeting rule.universe, tradeability, term and score requirements
    if frame_unavailable or no_next_session_for_fills: record_and_skip(T)
    else if eligible is empty: report_for_review(T)   # 空池处置尚非原站已证行为
    else:
        rank inputs inside eligible if the rule needs percentiles
        ranked = sort(eligible, key=(rule.score_small_is_better, bond_code))
        k = ceil(len(eligible)/6) if fraction_variant else min(top_n, len(eligible))
        emit(T, [(r.bond_code, 1/k) for r in ranked[:k]], full_target=True)
        log(rule_version, snapshot_hash, candidate_count, exclusion_counts, k, ranks)
```

## 执行和事件边界

- 36 条旧规格都写明 `t_close_to_t1_close_v1`、`price_only_v1`、初始 100 万、买卖单边各 10bp；本规范四条的旧运行基准是 `000832`，股票/其他类别不能套该基准。完整目标截面进入 `holding-plan-v1`：T 日收盘信号，正常在下一个**市场交易日**收盘成交，新截面未列出的旧券目标为零。目标等权与实际权重可能不同。
- 旧双低前 1/6 代表运行（`run-20260812-094916-28fabe14`）含 `filled` 2477、`partial_cash` 2557、`deferred` 63、`terminal_price_proxy` 2 笔；小数持仓证明未统一按整手取整。异常缺价、停牌、零成交量可延期，现金约束可部分成交。凭这些记录不能确定买卖顺序、延迟上限、交易冲突优先级、代理定价与触发条件的完整实现。
- `price_only_v1` 未完整核算票息、强赎、回售、到期和退市现金流。原报告无强赎入池筛选约定的规则不要私加，退出代理代表无后续行情时的估值处置，不能当真实兑付价；正式湖存在赎回公告数据集也不代表已覆盖全部事件或取得原站规则。如另做事件感知版本，应单独标注规则和版本，并按在 T 日已知的公告与可交易日期决定过滤及结算。
- 复用 E6 旧核对：双低前 1/6 与 CatBoost 十组两个运行的累计收益、最大回撤重算误差为零，成交费用在浮点精度内对齐；双低代表运行累计 56.1505%、最大回撤 −19.2351%、总费用 37,473.80 元。这是已发生交易的记账证据，不代表本轮从行情模拟成交，也不证明因子模型已还原。

## 独立截面检查

旧报告的 40/40、43/43、20/20 和 42/43 来自用原目标数截断排序；可用于名单比对，不验证选取数量。新检查只用三个已归档看板截面，从有限正收盘、期限 ≥0.5 年、有效排序字段独立求候选和 `k`，再对原目标及其 `reason` 中记录的顺位核对。看板截面没有原回测候选历史全集或信号日成交量，因而这是**快照字段的可复算规则**，覆盖不了完整池定义。旧 10 日变体用 20 日字段替代的结果不作证明。

五个原目标截面均为等权（最大绝对误差 < 4×10⁻¹⁸）。R1、R2 多选的都是 `113658`；同日该券在快照里收盘 140.738、剩余 1.2129 年、溢价 8.21 个百分点。证据只能确认它是本轮多选券，不能确认它为何未入原篮子、或它就是候选池唯一差异。R4 加看板 `momentumEligible` 后仍为 259，无法解释分母。R3 的两期结果证明从已发布因子恢复历史样本排序和等权；不证明由价格、条款重算了隐波，或所有日期都一致。

重跑本轮审查（仓库根目录，Python 3.9+，无需联网、数据湖或额外依赖）：

```sh
python3 docs/strategy-research/check_pool.py
python3 docs/strategy-research/check_pool.py --compare-archive "<EVIDENCE_ROOT>"
```

只跑第一条即可复核已提交的小样本；第二条用归档清单校验原 8 份响应的 SHA-256，再核对投影与夹具相同。[夹具](pool-fixture.json)只含三个完整快照的必要字段和五组原目标的 `代码 → [权重, 名次, 原池规模]`；它不含逐日行情、客户数据、曲线或原始响应。脚本先推导目标数量和排序，再读参考答案；未达到表中预期即退出失败。

## 湖侧输入与接入顺序

正式湖只读抽样 `cb_daily` 四个交易日（E7；仅计算覆盖，不做榜单拟合）。平价对应 `cb_value`，转股溢价对应 `cb_over_rate`。四个截面中当日正价且正成交量的记录均有两个字段；这还未核对期限、历史上市状态、口径精度或原站名单。

下一步先用日线、`cb_profiles` 和 `trading_calendar` 验证 R4 两端价格及历史准入，所需输入最少；R1、R2 共用该池，先用日线估值，只有在需要核对估值来源时才查 `cb_convert_price_panel` 和同日正股原始价。面板覆盖是价格观察，不等于在历史 T 日已知；样本 11 月 3 日未见有效面板重叠，不能用最新转股价填补。R3 日线表没有 IV 字段，需另定正股复权、条款、利率和历史 IV 的输入合同，成本最高。两条 259/258 的差异须解释后再扩大样本。

如另做执行接入，先冻结停牌、现金不足和到期／强赎样例，避免把退出价格代理和真实兑付混用。本轮未拉取新历史或跑全量策略。
