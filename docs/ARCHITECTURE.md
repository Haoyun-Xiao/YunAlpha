# YunAlpha 整体架构

本文记录目标设计。第一阶段已接入首批成果，第二阶段已迁入八个投研台、FOF 和现有基金研究 Agent。后续能力按 [阶段路线](ROADMAP.md) 推进。

## 产品与导航

产品品牌为 YunAlpha，仓库目录暂保持“综合投研平台”。参考 VIC 的侧栏、模块卡片、会话历史、详情与成果展示交互；替换 Logo、名称、文案和默认内容。技术栈继续采用 React/TypeScript/Vite、FastAPI 和独立 Worker。参考交互不等于直接使用原站编译包或依赖其业务接口。

| 导航 | 职责 | 建设安排 |
|---|---|---|
| 新建会话、个人空间与会话历史 | 统一研究 Agent 与成果入口 | 已接入迁入的基金 Agent，真实问答已验收 |
| 投研台 | 具体看板、分析工具、研究报告模块 | 第一阶段重点 |
| 策略 | 策略目录、回测、结果、组合管理 | 首期接入已有能力 |
| 深入 | 个别行业和公司的长期研究项目 | 最后建设，当前仅预留 |
| 自选、信号、Skills、任务、广场 | 未来功能入口 | 保留，未实现时明确标注未开放 |

自选未来以关注列表、简单信息和报告入口为主，不建设完整基金行情终端；它不再是第一阶段的建设中心。

## 投研台

以一个个具体模块组织，不按基金、股票、行业分别建大型子平台。公募抱团、公募持仓、基金深度报告可以同属主动基金组；逆向投资可以是独立模块。资产类型用于分组或标签，同一模块可以属于多个分类，避免重复实现。

模块内以看板、工具和报告展示为主，不含独立 Agent 或策略执行流程。后续可提供“继续研究”入口，将上下文传给统一 Agent。

优先接入已有基金深度报告，保留报告内部设计。配置报告继续保留，是否合并进深度报告及其撰写流程另行讨论。指增研究流程后续设计，可转债只融合已有能力。

公募抱团、国家队全景、逆向投资、情绪温度计、全 A 筹码结构、市场估值、A 股公募持仓、A 股资金流八个投研台均已迁入。保留已实现交互及数据缺口说明，未完成部分在 YunAlpha 继续开发。

## 策略

采用 VIC 式目录和交互，内容换成自己的普林格、大类资产模型、红利低波等策略。FOF 保留手动配置、回测、调仓和组合管理，不简化为单一策略表单。

统一导航、说明与结果入口，各策略保留专属操作。页面复现不代表算法已实现；数据口径与执行能力以真实旧项目为准。王涿可转债平台策略库已进入独立证据复核与规则研究；先区分已恢复规则、历史持仓重放和未知算法，业务策略接入以逐项验证为准。VIC其他策略后续再排期。

## 研究 Agent

先迁入现有基金研究 Agent：新会话前端连接原后端，保留现有工具和工作流，适配消息、进度、报告产物，数据访问统一接入数据湖。迁移阶段不重写 Agent 架构、不扩展研究方法。

投研台和策略成熟后，再扩展 Agent 的检索、调用和联动。研究材料、报告和策略说明进入知识库；查询、计算、报告生成和回测封装为工具或工作流。报告可独立访问，不要求先进入聊天。

市场点查默认读取正式数据湖。DS 会话可按需通过 Tushare 代理 MCP 查单日交易日历、股票未复权日线和核对来源。见[市场查数与代理 MCP](tasks/agent-market-mcp.md)。

## 数据与服务

### 产业链研究扩展

根据追加任务，将原产业链研究 Agent 的七阶段工作流迁入 `apps/fund_agent/src/industry_agent`，通过统一 Agent 的 `industry_research` 工具创建后台任务，并提供状态、成果读取、恢复和取消工具。与基金报告共用 API、Worker 和模型配置，分别保存任务状态。

`deep_skills/industry-research` 是唯一的方法来源，Skills 页面读取实际目录并提供会话入口。流程保留取材、结构、冻结数据、环节研究、独立审核、综合与导出；正式数据湖只读，成果在 YunAlpha 本地保存。该功能不依赖原产业链项目的环境、进程或文件路径。

```text
YunAlpha 前端：投研台 / 策略 / 会话 / 深入及其他预留入口
                         ↓
FastAPI 应用服务 + 已有研究、策略后端 + 业务 Worker
                         ↓
统一数据湖 / 研究知识库 / 应用状态与成果索引

后期 Autoloop 中台 → 调度业务执行入口、更新与提醒
独立本地量化实验 → 共用数据湖和中台，最后选型实施
```

数据湖提供正式结构化数据；知识库负责研究材料的检索与引用；自选、对话、任务、组合配置与成果索引属于应用状态，不强行全部放进数据湖。正式数据湖默认只读，新增数据与成果走湖侧明确发布流程，应用不直接覆盖历史数据。

数据湖与中台继续独立管理。前端的数据接口由应用服务承担。本机日更由 YunAlpha 的入口协调数据湖更新和投研台刷新，两段分别记录状态。macOS 负责定时和登录触发，DSH 通过 OpenCodex 调用固定 DS 模型协助续跑。中台后续可调用同一命令并读取回执，取数和计算仍由原模块负责。见 [日更说明](tasks/daily-update.md)。

## 深入与扩展

“深入”面向个别行业和公司的长期研究，允许每个项目拥有不同的材料、模型、问题和结论结构，不套量产报告模板。当前只预留入口，不开发通用研究引擎。

后续按具体需要使用 REA 获取前端布局、交互与运行证据，不以逆向整个网站为前置条件。保留来源记录，产品界面统一为 YunAlpha。
